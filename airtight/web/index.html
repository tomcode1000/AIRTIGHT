Write to memory before you pay.

An agent killed mid-payment cannot tell whether the money left. Retry and it pays twice. Sit still and it holds nothing. AIRTIGHT records the signed payment before the money moves — so waking up is never a guess.

Write before you act, never after.

Every payment carries a nonce the token contract honours exactly once. That nonce is the only thing making a payment unrepeatable — so it goes into memory before it is ever submitted.

Killed inside that window, the agent wakes holding the signed authorisation and submits that exact one again. Same nonce, so the contract either settles it for the first time or refuses it outright. It never has to work out which — the chain already knows.

Delete the memory and it stops paying.

If a product still works once its memory is removed, the memory was never load-bearing. With no verifiable record, this agent will not sign and will not pay — because starting over is how you pay twice.

The two shaded rows carry the argument. Killed at IN_FLIGHT the payment had not landed, so it re-submitted and settled once. Killed at SETTLED it had landed but was not yet recorded — it re-submitted the same authorisation and the chain refused it.

It is a layer, not an app.

Four calls, in this order. The order is the product.

// 1. on wake, ask what you may do. never assume.
const v = assessDeal({ deal, attestations });
if (v.verdict !== 'RESUME') return; // REFUSAL, or DISPUTED with evidence

// 2. sign, 3. store, THEN 4. pay — this order is the whole thing
const signed = signPayment({ privateKey, requirements });
await mem.claimFingerprint(signed.fingerprint, deal.deal_id);
await mem.transition(deal.deal_id, 'IN_FLIGHT', {
  payment: { x402: signed.stored },
});
await submitPayment(url, signed.header);
